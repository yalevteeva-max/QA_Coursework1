# Отчет об автоматизации

1. Что было запланировано и что реализовано
Запланировано - автоматизация 10 сценариев (оплата, кредит, валидация полей, проверка БД).
Реализовано - написано 4 автотеста: успешная оплата, успешный кредит, проверка записи в БД после оплаты, а также негативный сценарий (отказ по кредиту с картой DECLINED). 

1. Причины, по которым что-то не было реализовано
Основной упор был сделан на самые критичные бизнес-процессы (оплата и кредит). Тесты на валидацию полей (например, поле Владелец) не были автоматизированы, чтобы уложиться в сроки, но дефекты зафиксированы в Issues.

1. Сработавшие риски
Проблемы с Docker на Windows - был конфликт портов (3306 был занят), решено переназначением на порт 3307 в docker-compose.yml.
* Сложности с поиском локаторов - в приложении отсутствуют атрибуты name или id у полей ввода. Решено поиском элементов по CSS-классам input.input__control и заполнением по порядку.
* Асинхронность приложения - Тест на проверку БД требует ожидания, так как запись в базу происходит с задержкой.

1. Общий итог по времени
* Запланировано - 26–36 часов.
* Потрачено ~25 часов.
* Обоснование расхождения - часть тестов была написана быстрее за счет использования общих фикстур и единой структуры, но настройка Docker и поиск локаторов заняли больше времени, чем планировалось.
## Примечание по СУБД (PostgreSQL)

В рамках курсового проекта развертывание и тестирование проводилось на СУБД MySQL.

Однако, с учетом требования о поддержке приложением двух СУБД, в файл docker-compose.yml был добавлен контейнер postgres, а в conftest.py реализована фикстура db_connection_postgres для подключения к ней. 

Для запуска автотестов на PostgreSQL требуется переконфигурировать приложение aqa-shop(заменить JDBC URL с MySQL на PostgreSQL), что выходит за рамки текущей итерации, но архитектурная готовность тестов к работе с обеими СУБД реализована.
