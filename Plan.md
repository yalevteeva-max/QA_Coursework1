# План автоматизации тестирования

## 1. Перечень автоматизируемых сценариев

Позитивные сценарии (UI):
1. Успешная покупка тура по дебетовой карте (карта 4444 4444 4444 4441, статус APPROVED).
2. Успешная выдача кредита по данным карты (карта 4444 4444 4444 4441, статус APPROVED).

Негативные сценарии (UI):
3. Отказ в покупке тура по дебетовой карте (карта 4444 4444 4444 4442, статус DECLINED).
4. Отказ в выдаче кредита (карта 4444 4444 4444 4442, статус DECLINED).
5. Отправка формы с пустыми полями (проверка валидации).
6. Отправка формы с неверным форматом данных (например, буквы в номере карты, неверный срок действия карты).
7. Проверка валидации срока действия карты: ввод истёкшего срока (например, 01/22). Ожидается сообщение «Истёк срок действия карты».
8. Проверка валидации формата номера карты: ввод букв или слишком короткого номера.
9. Проверка валидации поля CVC: ввод двух цифр вместо трёх или букв.
10. Проверка поля Владелец (кириллица, спецсимволы, длинна)
11. Проверка текстов ошибок для пустых полей

Проверка работы с СУБД (SQL-запросы):
1.  Проверка записи в БД после успешной оплаты (статус должен быть APPROVED).
2.  Проверка записи в БД после отказа (статус должен быть DECLINED).
3.  Проверка того, что данные карты (номер, CVC) не сохраняются в БД в открытом виде.

## 2. Перечень используемых инструментов с обоснованием выбора
* Python 3 - язык программирования для написания тестов .
* Pytest - удобный фреймворк для запуска тестов, поддерживает фикстуры и параметризацию.
* Selenium WebDriver - для автоматизации UI-тестирования (взаимодействие с браузером).
* Allure - для генерации наглядных отчётов о прохождении тестов.
* Requests / PyMySQL - для отправки SQL-запросов и проверки данных в базе данных.
* Docker / Docker Compose - для развертывания приложения, СУБД и эмулятора платежного шлюза в изолированных контейнерах.

## 3. Перечень  возможных рисков при автоматизации
* Риск 1. Проблемы с Docker на Windows. Возможны конфликты портов например, занят порт 3306 или проблемы с виртуализацией. Решение - переназначение портов.
* Риск 2. Нестабильность эмулятора платежей. Эмулятор может медленно отвечать или выдавать ошибки при частых запросах. Решение - добавление явных ожиданий (WebDriverWait) в тестах.
* Риск 3. Поиск багов в приложении. Найденные баги (например, неверная обработка статуса DECLINED) могут ронять позитивные тесты. Решение - описание багов в Issues, корректировка ожидаемых результатов в тестах.
* Риск 4. Нехватка времени.Решение - приоритизация сценариев (сначала самые критичные — оплата и кредит).

## 4. Оценка времени с учётом рисков
* Развертывание окружения ≈ 3-6 часов.
* Написание UI-тестов (позитивные/негативные) ≈ 6-8 часов.
* Написание тестов для проверки БД ≈ 5-6 часов.
* Генерация Allure-отчётов и оформление документации (README, Report, Summary) ≈ 4-6 часов.
* Итого ≈ 16-21 часов (с учётом рисков).
